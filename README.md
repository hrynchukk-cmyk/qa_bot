# QA Design Bot

Бот для автоматичного тестування дизайну (верстки) сайтів. Приймає URL сайту,
відкриває його в різних розширеннях екрана та перевіряє верстку, елементи,
тексти, зображення тощо. Опційно порівнює сторінку з макетом Figma —
попіксельно, зі знімком різниці.

Результат — HTML-звіт зі скриншотами кожного розширення та машиночитний
`report.json`. До кожного зауваження, що стосується конкретного елемента,
додається фрагмент скриншота з цим елементом, обведеним червоною рамкою.

## Що перевіряє

| Перевірка | Рівень | Опис |
|---|---|---|
| Горизонтальний скрол | помилка | контент ширший за екран |
| Вихід за межі екрана | попередження | конкретні елементи, що вилазять за viewport (із CSS-селектором) |
| Перекриття елементів | попередження | тексти/зображення/кнопки, що налазять одне на одного |
| Обрізаний текст | попередження | текст не вміщується в блок і обрізається (`overflow: hidden`) |
| Дрібний шрифт | попередження | текст менший за 12px |
| Биті зображення | помилка | зображення не завантажилися |
| Спотворені зображення | попередження | порушені пропорції (розтягнуті/стиснуті) |
| Малі елементи натискання | попередження | кнопки/посилання менші за 24×24px на мобільних (WCAG 2.5.8) |
| Meta viewport | помилка | відсутній `<meta name="viewport">` |
| JS-помилки | помилка | необроблені винятки на сторінці |
| Помилки в консолі | попередження | `console.error` під час завантаження |
| Невдалі запити | попередження | ресурси з відповіддю 4xx/5xx |
| Зображення без alt | зауваження | доступність |
| Атрибут lang | зауваження | доступність |

## Встановлення

```bash
npm install
npx playwright install chromium   # якщо Chromium ще не встановлено
```

## Використання

### Веб-інтерфейс для замовника

```bash
npm start               # відкрийте http://localhost:3000
```

Замовник вставляє посилання на сайт, за бажанням розгортає блок «Порівняти з
макетом Figma» і додає посилання на макет — бот тестує сайт і показує звіт
прямо на сторінці (з живим логом прогресу). Завдання виконуються по черзі,
звіти зберігаються в теці `runs/` і доступні за посиланням `/reports/<id>/`.

Налаштування сервера: `PORT` (типово 3000), `QA_BOT_RUNS_DIR` (тека звітів),
`FIGMA_TOKEN` (спільний токен — тоді замовнику не треба вводити свій).

### CLI: без макета (тестування верстки)

```bash
npx qa-bot https://example.com
```

Розширення за замовчуванням: `390x844` (mobile), `768x1024` (tablet),
`1366x768` (laptop), `1920x1080` (desktop). Свої:

```bash
npx qa-bot https://example.com -v "360x800,414x896,1440x900"
```

### CLI: з макетом Figma (порівняння)

Замовник надає посилання на файл або конкретний фрейм Figma:

```bash
export FIGMA_TOKEN="figd_..."
npx qa-bot https://example.com --figma "https://www.figma.com/design/КЛЮЧ/Назва?node-id=1-23"
```

Як це працює:

1. Бот забирає фрейми з Figma (за `node-id` — конкретний фрейм; без нього —
   всі фрейми першої сторінки файлу, до `--figma-frames`, типово 8).
2. Кожен фрейм експортується як PNG через Figma API.
3. Сайт відкривається у viewport із шириною фрейму, робиться скриншот.
4. Зображення порівнюються попіксельно (спільна область зверху) —
   у звіт потрапляють макет, скриншот, знімок різниці та % розбіжності.

Токен Figma: **Figma → Settings → Security → Personal access tokens**
(достатньо права `File content: read`). Передається через `--figma-token`
або змінну середовища `FIGMA_TOKEN`.

### Основні опції

| Опція | Типово | Опис |
|---|---|---|
| `-v, --viewports <list>` | 4 стандартні | розширення: `"390x844,1920x1080"` або `"mobile:390x844"` |
| `-o, --out <dir>` | `qa-report` | тека для звіту |
| `--figma <url>` | — | посилання на файл/фрейм Figma |
| `--figma-token <token>` | `$FIGMA_TOKEN` | персональний токен Figma |
| `--figma-threshold <pct>` | `5` | % розбіжності пікселів, що вважається нормою |
| `--wait <ms>` | `800` | додаткове очікування після завантаження (анімації, шрифти) |
| `--timeout <ms>` | `45000` | таймаут завантаження сторінки |
| `--fail-on <level>` | `never` | `error`/`warning` — вихід із кодом 1 для CI |

### Програмний API

```js
import { runAudit } from 'qa-design-bot';

const report = await runAudit({
  url: 'https://example.com',
  outDir: 'qa-report',
  // figma: { url: 'https://www.figma.com/design/...', token: process.env.FIGMA_TOKEN },
});
console.log(report.summary); // { errors, warnings, infos }
```

`runAudit` повертає повний об'єкт звіту й записує в `outDir`:

```
qa-report/
├── index.html        ← звіт для людини (відкрити в браузері)
├── report.json       ← структуровані дані для інтеграцій
├── screenshots/      ← повні скриншоти кожного розширення
├── elements/         ← фрагменти з проблемними елементами (червона рамка)
└── figma/            ← макет / сайт / різниця для кожного фрейму
```

## Демо

Репозиторій містить демо-сторінку з навмисними помилками верстки:

```bash
npm run demo    # підніме локальний сервер, прожене аудит, збере звіт у demo-report/
npm test        # юніт-тести
```

## Обмеження v1 та план розвитку

- Порівняння з Figma попіксельне: динамічний контент (банери, каруселі) дає
  розбіжності — дивіться знімок різниці очима.
- Перевірка перекриттів — евристика; фіксовані шапки та навмисні оверлеї
  пропускаються, але поодинокі хибні спрацювання можливі.
- Тестується одна сторінка за запуск (можна викликати кілька разів).

Далі: обхід кількох сторінок сайту, Telegram/Slack-інтерфейс для замовників,
порівняння скриншотів між запусками (регресія), перевірка контрастності текстів.
